# PRD Index

PRD documents define product intent and user-visible requirements. They answer
who the product serves, what outcomes matter, which scenarios are supported, and
what is out of scope.

PRD documents should not own source paths, DTO shapes, route names, or detailed
implementation mechanics. Use design docs for feature behavior, spec/protocol
docs for technical contracts, and code docs for source ownership.

## Boundary
- Put product goals, users, non-goals, and release constraints here.
- Put user operating instructions in [guide](../guide/README.md).
- Put feature UX/state behavior in [design](../design/README.md).
- Put runtime contracts in [spec](../spec/README.md).
- Put source-code ownership in [code](../code/README.md).

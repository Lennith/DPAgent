# DPAgent Release Notes: 1.0.20 - 1.0.38

本文基于当前仓库 git history 和 `package.json` 版本变更整理，只描述用户可感知的功能、体验和发布门禁变化，不展开具体代码实现。

版本边界说明：

- 当前仓库没有 release tag，本文件以 `package.json` 版本变更提交和相邻提交区间作为版本边界。
- `1.0.38` 按当前测试版本处理，对应当前 working tree 中尚未提交的改动。
- `1.0.23`、`1.0.29`、`1.0.30`、`1.0.31`、`1.0.36` 未发现独立发布边界，按跳号/并入后续版本说明。

## 1.0.20

依据：`1b46d59`

- 优化聊天治理界面，思考内容、工具调用、工具结果和消息展示更清晰，降低主聊天区噪音。
- Todo 面板改为围绕 Agent 当前执行任务展示，让用户更容易理解 Ralph/自动循环正在推进什么。
- Sub-Agent 面板增加治理、记忆整理等入口，后台治理状态更容易被发现。
- 自动迭代相关配置、停止操作、轮次和状态文案更清晰。
- 版本边界从 `1.0.18` 直接进入 `1.0.20`，未发现 `1.0.19` 独立发布内容。

## 1.0.21

依据：`102f83e`, `fec799f`

- 修正 Agent Profile 注入与会话历史的关系，使用 `@agent` 或预设 Agent 时上下文更稳定。
- 同一工作目录下多个 session 并行使用时，历史、运行状态和取消操作隔离更可靠。
- 长会话上下文恢复从旧的 history anchor 收敛到压缩历史上下文，长对话回放和压缩表现更稳定。
- MCP 默认配置、共享运行时和工具注册去重能力增强，减少重复初始化和工具状态异常。
- 补充上下文相关文档，明确长会话、压缩历史和运行态上下文的使用边界。

## 1.0.22

依据：`9f94963`

- 明确区分三类上下文入口：当前结构化上下文检查、历史会话原文搜索、长期记忆管理。
- 强化当前上下文检查能力，可诊断 pending overlay、压缩历史、工具集和记忆状态。
- 自动迭代增加完成标记要求，减少“只说完成但任务未闭环”的提前收尾。
- Todo 驱动的 Ralph Loop 更严格：有未完成事项时继续推进，全部完成或明确阻塞后才停止。
- 新增完成标记评估能力，用于验证自动循环是否真正完成任务。

## 1.0.24

依据：`8771ae6`

- Web UI 增加国际化能力，核心面板、配置、会话、Todo、Sub-Agent 等文案支持本地化，默认中文体验更完整。
- 工作区选择体验增强，可保存默认工作区，新建会话默认使用用户偏好的工作目录。
- 文件和 Shell 工具增加 full-access 工作区权限约束，降低误操作非目标目录的风险。
- Composer 中的目标 Agent 选择移动到快捷操作区域，减少与工作区选择控件的布局冲突。
- 响应式布局继续优化，侧栏、聊天区和 Sub-Agent 面板在不同窗口宽度下更可用。

## 1.0.25

依据：`d73d65d`

- 新增自动化中心，可创建、编辑、启停自动化任务。
- 自动化任务支持按小时、每天、每周调度，并可指定工作区、时区和可选技能。
- 可查看自动化执行记录，并从记录打开对应会话，便于追踪后台任务结果。
- 支持从自动化执行会话沉淀或修正自动化记忆模板，让后续任务复用经验。
- 自动化表单更新、调度隔离和执行结果记录更稳定；记忆同步失败不再直接覆盖任务执行成功状态。

## 1.0.26

依据：`e5d67a2`

- 修复 Ralph/Sub-Agent 面板布局，在主聊天区和右侧面板同时显示时减少挤压和溢出。
- 调整面板高度和滚动体验，Sub-Agent 任务区、记忆区和审计区更稳定可读。
- 本版本主要是 UI 稳定性修复和版本号提升，无新增大型功能。

## 1.0.27

依据：`fe280c9`, `cf8bdfa`, `de6f8a0`, `a6f219c`, `10cb74d`

- Web 服务、会话路由、WebSocket 和回调续跑流程收敛，长任务和会话操作更稳定。
- 前端主应用状态拆分后，工作区、会话和治理状态切换更可靠，降低跨会话状态错位风险。
- 上下文管理和完整性检查边界收敛，长会话恢复和历史回放可靠性增强。
- 运行时启动、核心服务和执行工具装配更稳定，为后续 provider、tool replay 和治理能力打基础。
- 本版本以稳定性、结构收敛和长上下文验证为主，独立新功能较少。

## 1.0.28

依据：`1121a38`

- 新增自动生成 Skill 的治理能力，可扫描生成 Skill、识别重复或冲突候选，并产出治理报告。
- 自动化中心支持立即执行，运行记录区分手动触发和定时触发。
- 内置系统自动化任务标记为只读，避免用户误改治理类系统任务。
- 自动化运行增加重叠执行保护，已有运行未结束时会跳过新一轮，减少重复任务互相干扰。
- Skill 草稿、加载和治理审计流程更完整，生成 Skill 的生命周期更可控。

## 1.0.32

依据：`76d4101`

- 增加 provider 路由能力，支持 Anthropic 风格 provider 和 OpenAI-compatible provider，并可通过配置、API 和 Web UI 切换。
- MiniMax OpenAI-compatible 使用路径纳入验证，发布包在干净安装后也能加载对应 provider。
- 交互式用户输入工具统一为 `request_user_input`，减少多工具别名带来的歧义。
- Web 搜索和抓取工具名统一为 `web_search`、`web_fetch`，工具选择更明确。
- 待用户补充输入的会话支持在 UI 中恢复提示，降低刷新或切换会话后丢失待处理问题的风险。
- 增加工具调用长上下文发布门禁，强化多轮工具调用历史回放和发布前稳定性验证。

## 1.0.33

依据：`e65d43b`, `7006200`

- Todo 协议收敛为先设置完整计划、再逐项更新状态，多步骤任务表达更清晰。
- 已完成 Todo 在带有完成证据后进入更稳定的归档状态，降低历史完成项被误改的风险。
- 新增 completion marker 强制开关，默认关闭，可按需要启用自动循环完成标记约束。
- Provider Center 上线，可管理主聊天 LLM Profile、默认 Profile、模型发现、reasoning/thinking 等运行时选项。
- 主聊天增加会话级 LLM 控制能力，可在当前会话内切换 Provider/Profile、模型和推理强度。
- 发布流程绑定更严格的多轮工具调用评估和人工复核产物，发布证据与源码状态关联更明确。

## 1.0.34

依据：`4de18e8`, `42fb311`

- 工具调用历史回放在 Anthropic 与 OpenAI-compatible provider 间统一，降低长会话中工具结果错位导致的中断。
- Provider 适配器面对异常或不完整工具调用历史时更稳健，优先提供可恢复上下文而不是直接失败。
- 聊天实时工具调用展示支持先显示工具名、再补齐最终参数，流式过程更自然。
- 修复并行工具调用在会话运行态中的更新问题，避免多个工具同时出现时 UI 状态覆盖或重复。
- 工具协议回放规则更一致，为跨 provider 会话连续性打基础。

## 1.0.37

依据：`4e7d426`

- 优化 Web 聊天主界面响应式布局，聊天区、输入区、右侧工具栏在宽屏、窄屏和竖屏下更稳定。
- 将子代理面板重组为右侧工具栏，并把 TodoList 放入工具栏底部，让聊天区更聚焦。
- 设置页新增治理/记忆入口，并优化 Provider 配置体验，支持草稿配置嗅探模型、自动模型发现和默认输出长度上限。
- 当前会话 LLM 控制前移到输入区，Provider/Profile、模型和推理强度切换更紧凑。
- 发版门禁从单模型长上下文回归升级为多 Provider/Profile 回归，覆盖 `kimi`、`deepseek`、`minimax` 三组工具连续性测试。
- 新增响应式 UI smoke，用于验证关键聊天布局在不同视口下不重叠、不溢出。

## 1.0.38

状态：当前测试中，对应 working tree 未提交改动

- 进一步收紧聊天界面排版，输入区、消息栏、LLM/Ralph 控件、设置弹窗和侧边栏在多分辨率下更紧凑，减少控件重叠和视口溢出。
- LLM 选择弹窗改为更明确的下拉交互，Provider、模型、推理强度菜单互斥展开，并向上弹出以适配输入区位置。
- Todo 协议统一使用 `task_id` 作为 Todo 条目 id，完成状态必须绑定该 Todo id 和证据，避免 `id` / `task_id` 混用。
- TodoList 展示完整状态，包括进行中、阻塞、待处理和已完成项；只要会话存在 Todo，右侧工具栏就能展示 TodoList。
- 多 Provider 会话回放更稳：保存 assistant 消息的 Provider/Profile/Model 元数据，只回放同一运行时可复用的 thinking，降低跨模型上下文污染风险。
- 发版和 UI smoke 覆盖继续补强，重点验证响应式布局、Provider 配置和工具协议回放。

# Skill Runtime

## Responsibility
Skill runtime manages governed, model-augmenting skill packages: discovery from
disk, runtime loading into prompts, direct model-requested skill writes,
write history, rollback, pack publication, and auto-generated skill governance.

## Source Paths
- `src/skills/`
- `src/tools/SkillTools.ts`

## Key Files
- `src/skills/SkillLoader.ts`: discovers skills from the filesystem, resolves
  precedence across workspace/global/user scopes, and produces prompt catalog
  entries for injection into system prompts.
- `src/skills/SkillWriteStore.ts`: manages applied skill write records,
  generated-suggestion state, and versioned storage.
- `src/skills/SkillPackStore.ts`: skill pack publication, activation, and
  deactivation with pack-level metadata and version tracking.
- `src/skills/AutoGeneratedSkillGovernanceService.ts`: validates
  approved auto-generated workspace skills for duplicates and boundary
  metadata issues within the current workspace only.
- `src/skills/skill-write-contracts.ts`: TypeScript types for skill write
  record states, transitions, and metadata.
- `src/skills/skill-write-utils.ts`: utility functions for write validation,
  normalization, and formatting.
- `src/skills/skill-markdown.ts`: Markdown parsing and generation for skill
  content.
- `src/skills/auto-generated-skill-governance-contracts.ts`: contracts for
  governance rules, checks, and reporting.
- `src/skills/auto-generated-skill-governance-utils.ts`: utilities for
  duplicate detection and boundary analysis.
- `src/tools/SkillTools.ts`: model-callable tools for skill operations
  (list, read, create/update manage).

## Runtime Contracts
Model-callable `skill_manage` create/update writes are applied immediately as
approved skills. The runtime does not expose a pending skill approval queue.
Skill loading precedence: workspace overrides global overrides user. Manual
auto-generated skill governance only touches Skill Manager generated workspace
skills under the selected workspace's `skills/` directory; global skills,
handwritten workspace skills, and pack skills are not in that governance scope.
Pack publication is atomic and versioned.

## Edit Guidance
- Keep review-only approval/rejection actions out of model-callable runtime
  tools; model-callable skill writes should use create/update only.
- Put new governance rules in `auto-generated-skill-governance-utils.ts` or
  the contracts file; keep `AutoGeneratedSkillGovernanceService.ts` as the
  orchestrator.
- Update `SkillLoader` precedence resolution when adding new scope types.
- Rebuild skill catalogs when pack activation state changes.
